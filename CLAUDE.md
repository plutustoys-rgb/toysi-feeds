## VPS (45.94.157.4)

Усі Python-скрипти виконуються через `/opt/plutustoys/venv/bin/python3` (venv з встановленими залежностями, зокрема `python-dotenv`). Голий `python3` у systemd `.service`-файлі резолвиться в системний Python без залежностей і падає — перевіряй це в КОЖНОМУ новому `.service`-файлі: або абсолютний шлях до venv-python в `ExecStart`, або явний `Environment=PATH=/opt/plutustoys/venv/bin:/usr/bin:/bin` перед ним.

**Ти НІКОЛИ не виконуєш SSH/SCP на VPS сама** — класифікатор середовища блокує вихідні з'єднання на довільні хости завжди, незалежно від дозволу власника в чаті. Це структурна межа інструмента, не політика. Read-only deploy-ключі ти реєструєш сама через `gh api` — успішно. Write-scoped ключі — класифікатор блокує, реєстрація завжди вручну власником; твоя робота — підготувати точну команду й публічний ключ, передати їх явно, не тримати "в голові".

## Rozetka

Rozetka НЕ має власної історії продажів. Жодна функція відбору/ранжування/ротації для Rozetka не повинна перевикористовувати Prom-логіку (`select_top_items()` тощо) — це необґрунтована аналогія, двічі прямо відхилена власником.

**Модель (ОНОВЛЕНО 2026-08-16, РОЗМОРОЗКА Крок 1 — задача власника найновіше-53):** `rozetka_static_selection.json` (round-trip через `feed-data`) тепер задає лише **MEMBERSHIP** — набір pid, уже поданих на Rozetka (щоб не робити нову хвилю модерації). ДАНІ товарів цього набору — **ЖИВІ** щопрогону: склад (`available`/`stock_quantity` за реальним stock Toysi), ціна (`decide_price_for_platform` з Rozetka-флором), фото — **чисті `images.prom.ua`** без вотермарки (`_clean_pictures`, фолбек на toysi). Раніше (2026-07-27—2026-08-16) весь знімок був ЗАМОРОЖЕНИЙ (ні склад, ні ціна, ні фото не мінялись, поки не пройде модерацію). **Крок 2** (розкатати повний живий каталог, не лише membership-набір) — окреме рішення, коли переконаємось, що чисті фото проходять модерацію Rozetka.

## Процес PR (РОБОЧИЙ механізм — не перебудовувати, дотримуватись)

Кожен PR проходить незалежний аудит ПЕРЕД мержем, без винятку. Аудит перевіряє живо (git show/diff, синтетичні тести), не на слово з опису PR.

**ЯК запускати аудит (важливо — інакше він «висне»):** аудит проганяється як **ВНУТРІШНЬОСЕСІЙНИЙ субагент** — сесія «Код» САМА викликає інструмент **Agent** (`subagent_type: general-purpose`) з аудит-промптом і ЧЕКАЄ вердикт у тому ж ході. **НЕ через `spawn_task`/чіп** — той лише кладе кнопку власнику, ніхто не клікає, аудит висить (реальна помилка 2026-08-17). Промпт аудиту — нижче в цьому файлі / у `BOOTSTRAP.md`, з номером PR; `GH_TOKEN` субагент бере через `git credential fill` (gh не залогінений).

**Порядок мержу (гейт):** субагент вертає вердикт → якщо **ЧИСТО**: створити маркер `rozetka_agent/.audit_ok` → `gh pr merge <N> --merge --delete-branch` → **прибрати `.audit_ok`**. Само-мерж на чистому аудиті — сталий дозвіл власника (2026-08-07). Якщо аудит НЕ чистий — виправити, НЕ мержити.

**Механічний запобіжник:** hook `PreToolUse(Bash)` (`~/.claude/settings.json` → `.claude/hooks/merge-guard.sh`) блокує `gh pr merge` для toysi-feeds, поки нема `.audit_ok`. Маркер ставиться ЛИШЕ після справжнього чистого аудиту — ставити його без аудиту (щоб «пройти» хук) заборонено (умова власника). Загальне «так роби»/«активуй» власника = дозвіл продовжити план, НЕ дозвіл на мерж.
