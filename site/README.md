# PlutusToys — статичний магазин (`plutustoys.com.ua`)

Власний сайт-магазин, що генерується з живого каталогу Toysi **без CMS/платформи**
(рішення брифу — сенс сайту: прибрати комісію маркетплейсу, а не платити ще одній платформі).

## Збірка

```bash
cd rozetka_agent
python site/build_site.py          # повний каталог
LIMIT=120 python site/build_site.py # швидкий демо-зріз
SITE_GA4_ID=G-XXXXXXXXXX SITE_META_PIXEL_ID=<цифри> python site/build_site.py # аналітика (без ID — без сніпетів; див. deploy/DEPLOY_SITE.md §5б)
SITE_LIQPAY_LIVE=1 python site/build_site.py # лише коли LiqPay бойовий: показує «оплата карткою» (футер, кошик, оферта); без прапорця сайт обіцяє лише накладений платіж
```

Генерує у `site/`: `index.html` (головна «Новинки» + категорії), `catalog.html`,
`category-<slug>.html` на кожну категорію, `product-<id>.html` на кожен товар,
`cart.html` (кошик + checkout), `index.json` (індекс клієнтського пошуку).
Ці файли — білд-вихід (у `.gitignore`); у репо лишаються **генератор + ассети**.

## Що в репо (комітимо)

- `build_site.py` — генератор.
- `assets/styles.css` — спільна палітра/компоненти (тепла палітра з дизайну SMM).
  Підключення з `?v=<sha1 вмісту, 8 hex>` (`build_site.asset_url`): /assets/ кешується браузером на добу, версія в URL змінюється лише з вмістом — фікс доїжджає до тих, хто вже був на сайті.
- `assets/app.js` — кошик (localStorage), лічильник, пошуковий оверлей, checkout.
- `category_texts.json` — вступні тексти категорій від SEO: `{"<slug>": "абзац 1

абзац 2"}` (slug = ім'я файлу категорії без `category-` і `.html`); показуються під H1 лише на 1-й сторінці категорії, HTML екранується; порожнє/нема slug → блоку нема.

## Ціноутворення

Ціна вітрини = `competitor_pricing.toysi_discounted_price(it) × 1.5` (без комісії маркетплейсу).
Каталог — увесь in-stock Toysi з фото (без відсікань за ціною чи категорією). Націнка як у EVA-фіді; жодних зв'язків із маркетплейсами.

## Статус / далі

- ✅ Фронт: головна, каталог, категорії, картки, кошик, пошук — зв'язана навігація.
- ⏳ Крок 3 (бекенд): `POST /api/order` на VPS → створення замовлення (`orders_db`/`order_pipeline`),

  email-підтвердження. У фронті checkout-форма вже збирає дані; сабміт — заглушка до бекенду.
- ⏸ Набори (bundle): механіку закладаємо, число знижки — рішення КОДВ+власник (OWNER_INBOX).
